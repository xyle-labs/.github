# Contributing to Xyle Labs

Start with the relevant project's README and contribution guide. Project-specific
instructions take precedence over these defaults.

- Use issues for questions, reproducible bugs and proposals. Discuss substantial
  changes before implementing them.
- Keep pull requests focused. Explain the problem, the resulting behavior and
  how you verified the change. Run the project's required checks and resolve
  review conversations before merging.
- Keep credentials, confidential client data, personal recordings and assistant
  sessions out of public files, issues and commit messages. Use small synthetic
  examples and enable the project's local security hooks when provided.
- Use a GitHub noreply commit address or the project's approved maintainer identity.
- Contribute only material you have the right to license under the receiving
  project's terms, and preserve third-party notices.
- Be respectful and constructive. Discuss the work without personal attacks.

For changes to this organization profile, check the Markdown, project descriptions
and links, and scan the staged content for secrets before opening a pull request.
Report suspected vulnerabilities privately as described in SECURITY.md.
